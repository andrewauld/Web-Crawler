# Web-Crawler

A command-line search engine built in Python that crawls [quotes.toscrape.com](https://quotes.toscrape.com/), builds an inverted index, and allows interactive querying with TF-IDF ranked results.

Built for COMP3011 Web Services and Web Data — Coursework 2.

## Overview

This tool implements a three-stage search engine pipeline:

1. **Crawl** — A BFS web crawler traverses the entire target site, respecting a 6-second politeness window between requests.
2. **Index** — An inverted index is built from the crawled pages, storing each word's frequency and positions on every page it appears in, alongside per-page token count metadata for TF-IDF ranking.
3. **Search** — An interactive CLI shell allows the user to query the index using AND/OR logic, inspect individual word postings, and retrieve morphologically related word suggestions.

## Prerequisites

- **Python 3.10 or higher** (required for the `X | Y` union type hint syntax used in the source)
- **pip** for installing dependencies

No additional parser installation is needed — the crawler uses Python's built-in `html.parser` via BeautifulSoup. NLTK punkt tokeniser data is downloaded automatically on first run if not already present.

## Usage

### Starting the Shell

Navigate into the `src/` directory and run `main.py`:

```bash
cd src
python main.py
```

You will see the prompt:

```
Search Engine ready. Type 'help' for available commands.
>
```

### Commands

#### `build`
Crawls the target website, builds the inverted index, and saves it to `data/index.json`. Progress is printed for each page crawled. **This command takes several minutes** due to the mandatory 6-second politeness delay between requests.

```
> build
Crawling https://quotes.toscrape.com/ ...
Crawling page 1: https://quotes.toscrape.com
Crawling page 2: https://quotes.toscrape.com/page/2
...
Crawled 55 pages.
Building index...
Index built. 2,143 unique words indexed.
Index saved to data/index.json.
```

---

#### `load`
Loads a previously built index from `data/index.json` into memory. Use this to avoid re-crawling on subsequent sessions.

```
> load
Index loaded from data/index.json. 2,143 unique words indexed.
```

---

#### `print <word>`
Prints the full postings list for a single word, showing every page it appears on along with its frequency and token positions on that page.

```
> print life
Postings for 'life':
  https://quotes.toscrape.com/
    frequency : 3
    positions : [4, 47, 103]
  https://quotes.toscrape.com/page/2/
    frequency : 1
    positions : [22]
```

---

#### `find <term> [term ...]`
Finds all pages containing **every** query term (AND logic), ranked by aggregate TF-IDF score. The most relevant pages appear first.

```
> find good friends
AND search results for: ['good', 'friends']
  1. https://quotes.toscrape.com/page/3/  (score: 0.0842)
  2. https://quotes.toscrape.com/page/7/  (score: 0.0611)
```

---

#### `find any <term> [term ...]`
Finds all pages containing **at least one** query term (OR logic), ranked by aggregate TF-IDF score.

```
> find any good friends
OR search results for: ['good', 'friends']
  1. https://quotes.toscrape.com/page/3/  (score: 0.1204)
  2. https://quotes.toscrape.com/page/1/  (score: 0.0731)
  3. https://quotes.toscrape.com/page/7/  (score: 0.0611)
```

---

#### `suggest <word>`
Suggests vocabulary words from the index that are morphologically related to the query word (i.e. share the same stem), using the NLTK Snowball stemmer.

```
> suggest friend
Suggestions for 'friend':
  friendly
  friends
  friendship
```

---

#### `help`
Prints a summary of all available commands.

```
> help
Available commands:
  build               Crawl the website and build the index
  load                Load the index from disk
  print <word>        Print the postings list for a word
  find <term(s)>      Find pages containing ALL terms (AND search)
  find any <term(s)>  Find pages containing ANY term (OR search)
  suggest <word>      Suggest related words from the index
  help                Show this help message
  quit                Exit the search tool
```

---

#### `quit` / `exit`
Exits the search tool.

```
> quit
Goodbye.
```

## Features

### Core Features

| Feature | Description |
|---|---|
| **BFS Web Crawler** | Traverses the full site breadth-first from the seed URL, following only same-domain links |
| **Politeness Window** | Enforces a minimum 6-second delay between successive HTTP requests |
| **Inverted Index** | Maps every word to the pages it appears on, storing frequency and 0-indexed token positions |
| **Case Insensitivity** | All text is lowercased at crawl time; queries are matched case-insensitively |
| **Index Persistence** | `build` saves the index to `data/index.json`; `load` restores it without re-crawling |
| **`print` command** | Displays the full postings list for any indexed word |
| **`find` command (AND)** | Returns pages containing all query terms, ranked by TF-IDF |
| **Error Handling** | Network failures and non-200 responses are logged and skipped gracefully |

### Advanced Features

#### TF-IDF Ranking
Search results are ranked using the standard TF-IDF formula:

```
TF(word, page)     = frequency(word, page) / total_tokens(page)
IDF(word)          = ln(total_pages / pages_containing_word)
TF-IDF(word, page) = TF × IDF
```

For multi-word queries, each page's score is the **sum of TF-IDF scores** across all query terms. This naturally promotes pages that contain more query terms (for OR searches) and pages where the terms appear more prominently relative to the page length.

Per-page token counts are stored in a `_meta` section of the index at build time, making TF computation efficient at query time without needing to re-parse any text.

#### OR Search (`find any`)
In addition to the standard AND search, `find any <terms>` performs a union-based retrieval, returning any page containing at least one of the query terms. Results are still TF-IDF ranked, meaning pages matching more terms score higher than those matching only one.

#### Query Suggestions (`suggest`)
The `suggest` command uses the NLTK Snowball stemmer to find vocabulary words in the index that share a morphological root with the query word. Stemming is applied **only at query time** — the index stores full, unmodified word forms. This preserves the integrity of `print` and `find` results while enabling flexible, root-based suggestion lookup.

## Architecture & Design

### Component Separation
The system is divided into three independent modules with a clear data flow:

```
crawler.py  →  list of {url, text} dicts
                        ↓
indexer.py  →  inverted index dict (saved as JSON)
                        ↓
search.py   →  ranked results / postings / suggestions
```

`main.py` is a thin wiring layer that owns the REPL loop and delegates all logic to the modules above. This separation means each component can be tested and reasoned about independently.

### Index Data Structure
The index is a nested Python dictionary with two types of top-level keys:

```python
{
    "_meta": {
        "https://quotes.toscrape.com/": { "total_tokens": 143 }
    },
    "world": {
        "https://quotes.toscrape.com/": {
            "frequency": 2,
            "positions": [4, 51]
        }
    }
}
```

- `_meta` is underscore-prefixed to prevent collision with any real vocabulary word
- The nested dict structure gives O(1) lookup by word, then O(1) lookup by URL
- JSON serialisation preserves the structure exactly and keeps the index human-readable

### Tokenisation
Text is split on whitespace and punctuation is stripped from token edges only (e.g. `"hello,"` → `"hello"`). Mid-word punctuation is preserved (e.g. `"it's"` stays `"it's"`). No stopword removal or stemming is applied to the index — every word form is stored as-is.

## Testing

Tests are written with `pytest` and cover all three core modules. All HTTP requests in crawler tests are mocked using `unittest.mock` — no real network calls are made during testing.

### Running all tests

From the project root:

```bash
pytest tests/
```

### Running with coverage report

```bash
pytest tests/ --cov=src --cov-report=term-missing
```

### Running a specific test file

```bash
pytest tests/test_crawler.py
pytest tests/test_indexer.py
pytest tests/test_search.py
```
